## JSON shape and IDs

Target > Stream > Category > Problem is reconstructed from existing Neo4j `HAS_STREAM` / `CONTAINS` relationships. Problem-only lateral edges use `RELATED_TO`, `CAUSES` and `SUPPORTED_BY`. The outer object has `id`, `name`, `type: target` and `children`. All hierarchical IDs and `crossLinks` are Neo4j `elementId()` values. A Problem has `value: 100`, `crossLinks` and an extra **`recordId` (number)** that the existing app needs to call `/api/targets/{tid}/problems/{pid}`. Problems have no `children` key; empty Targets/Streams/Categories retain an empty `children` array. The renderer alone adds a display-only value to empty structural branches. No permanent element ID is stored in SQLite.

Because no reliable type/rationale data for lateral relationships was part of the requested chart JSON contract, the endpoint does not claim causality or evidence grade in its lines. Missing/mismatched cross-target relationships are excluded. Evidence and concepts are research artifacts shown through existing details, not hierarchy levels in this initial view.

## Acceptance matrix — must be run on the actual installation

1. **Build:** npm resolves both local chart/panel dependencies, `npm run build` succeeds, and Vite loads without browser console exceptions.
2. **Tree contract:** empty Target, Target with streams only, full 498-reference Target, multiple streams/categories; output has one root, unique Neo4j element IDs and valid nested children.
3. **Graph UX:** wheel, pinch (if available), fit/zoom; initial root/stream view; stream/category expand/collapse; problem click opens modal without folding its branch; long statements readable by tooltip/modal.
4. **Cross-links:** `RELATED_TO`, `CAUSES` and `SUPPORTED_BY` Problem↔Problem relationships render only for nodes inside active Target. Relationships to other targets or findings never leak onto the graph.
5. **Panels:** independently open two or more workflow panels, drag via header, select and edit text inside forms without window motion, resize, collapse, reopen, refocus, reset positions, theme toggle and narrow screens.
6. **Research:** search lexical/semantic, create/edit/delete hierarchy items, research with source review, draft problem discovery/approval, manual and AI concepts, save drafts, match concepts, evaluate and inspect results. Confirm each action changes only active Target.
7. **Identity:** email/password and Google SSO; administrator console roles, status, daily AI allowances, index jobs; disabled accounts and AI quota exhaustion.
8. **Isolation:** private Target owned by user A is invisible to B; shared Target is readable but not writable; copying yields a private structural clone without transferred findings, concepts or embeddings.
9. **Stability:** confirm editing and deleting nodes invalidates the graph and does not require reload; no automatic reseed, no change to auth DB or Neo4j service config; full browser usability after switching Targets.
